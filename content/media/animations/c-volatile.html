without volatile
The compiler may cache the value
uint32_t flag;           // set by an ISR
while (flag == 0) { }   // wait
↓ optimiser
r0 = flag;              // read ONCE
loop: if (r0 == 0) goto loop;
Nothing in the loop changes flag, so the read is hoisted out: infinite loop.
with volatile
Every access is real
volatile uint32_t flag;
while (flag == 0) { }
↓ compiler
loop: r0 = flag;        // read EVERY time
      if (r0 == 0) goto loop;
Each read or write is an observable memory access: not removed, merged or kept in a register.
use it for
hardware registers · variables changed by an ISR · memory-mapped I/O
volatile does NOT mean
❌ atomic
❌ thread-safe
❌ race-free
❌ memory barrier
counter++ on a volatile is still load, add, store: two tasks can still lose an update.
