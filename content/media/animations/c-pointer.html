pointer arithmetic
p + n moves n elements, not n bytes
int32_t a[4];
int32_t *p = a;      // p = 0x2000
p + 1                // 0x2004  (+ 1 * sizeof(int32_t))
((char *)p) + 1      // 0x2001  (+ 1 * sizeof(char))
int32_t a[4] at 0x2000 (each cell = 4 bytes)

// elements, not 12 bytes
The result type is ptrdiff_t.
Pitfalls
· a[i] is *(a + i)
· arithmetic on void * is not standard C (GCC treats it as bytes)
· going more than one past the end of an array is undefined behaviour
