Core idea

Scope and lifetime are different things

  • Scope = where the name can be used (compile time).
  • Lifetime = how long the memory exists (run time).
  • static on a local variable keeps the scope local but makes the lifetime the whole program.

Reasoning

Why a local static lives in the Data segment

A stack frame is destroyed when the function returns. If a lived there, its value would vanish every time.

CallNormal local (stack)Static local (data)
1sta = 5, then 6, frame destroyeda = 5, then 6, stays
2ndfresh a = 5, then 6 againcontinues at 6, then 7
3rd6 again7, then 8

To remember the value, the variable must live somewhere that survives the return. That place is the Data (or BSS) segment. The compiler still hides the name from other functions, so only the name is local.

Bug

Normal local

int *bad() {
  int a = 5;
  return &a;  // dangling: frame gone
}

Safe

Static local

int *ok() {
  static int a = 5;
  return &a;  // memory still alive
}

Code

All combinations in one place

int g1 = 10;              // Data
int g2;                   // BSS
static int g3 = 20;       // Data (file-private)
static int g4;            // BSS (file-private)
const int g5 = 30;        // .rodata
static const int g6 = 40; // .rodata (file-private)

void f() {
  int a = 1;              // Stack
  const int b = 2;        // Stack (or folded)
  static int c = 3;       // Data
  static int d;           // BSS
  static const int e = 4; // .rodata
}

Pointers and strings

Two things to place: the pointer and its target

const char *p = "hello";  // p: Data (global) or Stack (local)
                          // "hello": .rodata
char arr[] = "hello";     // own writable copy (Data or Stack)
const char *const r = "yo"; // both read-only

p[0]='H' crashes (read-only literal). arr[0]='H' works (its own copy).

Gotchas

Remember these

  • const does not always mean read-only memory. A local const is on the stack.
  • In C++, a global const has internal linkage by default. In C it has external linkage.
  • Static and non-static globals use the same memory. Only visibility differs.
  • Statics are zero-initialized automatically. Normal locals hold garbage.
  • C++ static locals with non-constant initializers are initialized on first call, guarded by a hidden flag.
  • Exact sections depend on compiler and linker (GCC/Clang on Linux shown).

Summary

One line

The name is local, but the storage is global: static hides the name inside the function and keeps the memory alive for the whole program.
