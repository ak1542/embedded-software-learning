Task stack overflow detection (Cortex-M4)

Problem

Stack overflow on Cortex-M4

  • No automatic stack-limit check (PSPLIM exists only on ARMv8-M, like M33)
  • Stack grows down, so overflow means going below stack_base

Method 1

Fill pattern and watermark

  • Fill the whole stack with 0xA5A5A5A5 at task creation
  • Count untouched words from the bottom to get the free space
  • Free count near 0 means near overflow
void stack_fill(uint32_t *base, size_t words) {
  for (size_t i = 0; i < words; i++) base[i] = FILL;
}
size_t stack_free_words(const uint32_t *base) {
  size_t n = 0;
  while (base[n] == FILL) n++;
  return n;
}

Method 2

Check at every context switch

  • Run it in the scheduler right after saving A's SP
  • Catches overflow only at switch time
if (tcb->sp < tcb->stack_base + 8 ||
    tcb->stack_base[0] != FILL)
  stack_overflow_hook(tcb);

Method 3

MPU guard region

  • Small no-access region (about 32 bytes) at the stack bottom
  • Write into it raises a MemManage fault at the exact instruction
  • Reprogram the region in PendSV on every switch
  • Region size is a power of 2 and aligned to its size
  • M4 MPU is optional and has 8 regions, check your chip

Prevention

Habits

  • Compile with -fstack-usage to see per-function cost
  • Avoid big local arrays and deep recursion
  • Keep 25-30% margin over the measured watermark
  • MSP (used by ISRs) can overflow too, check it the same way
