# Revision aids (the "easy to revisit" part)

Pick per topic; most pages deserve a short **Revise** subsection at the end. Prefer fewer, better ones.

| Aid | When | How |
|---|---|---|
| **Quick recap** (3–7 bullets or a tiny table) | always for a topic with ≥ 3 pages or any long page | restate the core ideas in the user's own terms; put it at the top of the page or in the Revise page |
| **Common mistakes** | anywhere a point was ❌/🟡, or a classic trap exists | `CALLOUT("warning", …)` with "Mistake → why it happens → correct version" |
| **Review checklist** | skills/concepts the user should be able to explain | `TASKLIST` of "I can explain…" items; the site keeps ticks only while editing, so keep items short and testable |
| **Flashcards** | definitions, register meanings, acronyms | `flashcards.html`, 6–12 cards, question on front |
| **Quiz** | concepts with a right/wrong answer | `quiz.html`, 4–8 questions, each with a one-line "why" |
| **Cheat sheet** | commands, registers, formulas | one dense table with copyable code |

Guidelines
- Derive aids only from the approved notes (including approved additions); do not introduce new facts in a quiz.
- Questions test understanding, not memory of wording; wrong options should be plausible mistakes.
- Link the Revise page from the main page (`[Revise](#/s-topic-revise)`).
